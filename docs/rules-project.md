# Project rules: FFXIV Plugin Index

Purpose: project-specific rules that extend or tighten the global rules, plus any additional rule
prefixes this project introduces.

> Reminder: these rules may only add to or tighten the global rules. They may never weaken,
> contradict, or override them (M-01, M-04). A project rule that contradicts a global rule is
> invalid and must be removed.

## Added prefixes

None. This project introduces no prefixes of its own; the global ones in `rules/06-numbering.md`
cover everything here.

## Rules

### `X` index handling

- **X-01** `pluginmaster.json` is never edited by hand, and never staged as part of a change made
  here. It is generated by the workflow, and a hand edit is either overwritten on the next run or
  survives as a lie about a release. This tightens C-12 for the one file where a hand-written value
  would be published to every user.

- **X-02** A change to `plugins.json` is verified by reading the resolved `InternalName` and version
  in the build log, not by the colour of the run. This tightens D-07 for the specific failure this
  repository can produce: the script resolves whatever the newest release contains, so a plugin
  renamed without a new release resolves cleanly under its old name and the run is green. That case
  has already occurred once, see `decisions.md`.

- **X-03** The error handling in `scripts/build-index.ps1` is not simplified. Carrying a previous
  entry forward when a repository cannot be read looks like sloppy code and is D-06 in force. Any
  change to that path states, in the commit message, what happens to a listed plugin when GitHub is
  briefly unreachable.

### Working documents

`how-the-index-works.md` and `adding-a-plugin.md` are working guidance, not a second rulebook. Where
they state something as a rule, they are restating a global rule (D-05, D-06, D-15, D-16) in the
words of this repository. If the two ever disagree, the foundation wins and the working document is
wrong.
